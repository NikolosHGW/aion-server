# C4 — серверная проверка классового боя и лечения

Дата: 2026-11-06. База изменений: `3ffcb4f2a`, ветка `integration/ai-4.8`.
Контракт и ограничения: [IMPLEMENTATION_PLAN_C4](IMPLEMENTATION_PLAN_C4.md).
Accepted ADR, журналы C1/C2/C3 и историческая `feature/ai-mvp` не менялись.

## Автоматические проверки

Offline reactor `mvn -o package -Dmaven.test.skip=false`, JDK 25.0.1, Maven 3.9.14:
**303 теста, failures/errors/skipped = 0/0/0** (game-server 297, login 5, commons 1).
Новые проверки: позднее завершение старого action; отменённый action не оживает;
синхронное завершение instant action; cast удерживает follow; границы короткого
подхода; порог лечения и поддержанные роли; освобождение собственной reservation
смертельного удара без изменения HP и без удаления чужой/обычной native пометки.
Существующий контракт Stage 2C с двумя методами сохранён без переписывания теста.

## Нативный сервер и restart

Запускается [CompanionC4RuntimeProbe](../../game-server/test/com/aionemu/gameserver/services/ai/CompanionC4RuntimeProbe.java).
Отдельная MariaDB 11.4, свежая схема `game-server/sql/aion_gs.sql`, host-only
порт `127.0.0.1:53412`, база `ai_c4_runtime`, контейнер с label
`codex.task=ai-companion-c4` и временным хранилищем. Рабочая БД не используется.
Probe имеет жёсткую проверку JDBC URL. GameServer использует отдельную конфигурацию
и порт 17782, native data и библиотеки собранного пакета.

Два отдельных JVM запуска: `create`, затем `restore`. Первый использует C3
fixture builder на чистой БД, загружает настоящие Player, skills, предметы,
геодату, Npc и skill engine. Второй загружает сохранённое состояние заново.
Вспомогательный `exercise` повторяет только C4 на уже подготовленной тестовой БД.

У fixture-владельцев нет AionConnection: тест проверяет domain/native execution
через явно подставленный lease admission, а **не настоящий вход двух клиентов**.
В рабочем CompanionService остаются проверки реального соединения владельца,
World identity, поколения сессии и owner/body attribution. Body не получает
fake connection и не записывается online. Probe не запускает production scheduler.

| Проверка | Результат / граница |
|---|---|
| Template audit четырёх разрешённых групп | Все текущие native ранги соответствуют single-target shape; это не бой на каждом уровне |
| Healing Light | Реальный cast, HP владельца увеличивается, MP тела тратится native механизмом |
| Отмена во время каста | Лечение не применяется; action становится CANCELLED |
| Skills flag выключен перед cast end | Асинхронная проверка отменяет cast без следующего AI tick, без траты MP и лечения |
| Нехватка MP | Native skill engine отказывает, cast не начинается |
| Потерянное разрешение сессии | Новый cast не начинается |
| Дальний владелец | Native range не разрешает лечение |
| Другой владелец | Его травма не вызывает лечение; чужая пара owner/body не проходит attribution |
| Авторизация NPC | Точный static spawn 210115 проходит существующие ограничения |
| Smite | Native эффект наносит реальный урон, включая lethal hit; включается native cooldown |
| Attribution | Физический спутник разрешается в своего владельца для FINAL_REWARD; отдельная доля спутнику не добавлялась |
| Flag выключен после cast end | Receipt ещё RUNNING до попадания; ожидающий эффект отменяется без урона |
| Отмена lethal hit | Собственная `isAboutToDie` reservation снимается, HP цели остаётся прежним |
| Серия гладиатора | Изученный Ferocious Strike открывает native chain state для Robust Blow; оба эффекта исполняются |
| Сохранение | После остановки действий/удаления из World checkpoint записывает точный остаток MP, до снятия пассивных эффектов |
| Restart | Потраченная MP и cooldown сохраняются; pending cast/соединение не восстанавливаются |
| Exact level 10 | Уровень профиля восстанавливается до stats/vitals; MP до progression точно совпадает с checkpoint; чужой класс отвергается |
| Quest journal | После native casts у тела нет строк в player_quests |

Native боевой сценарий использует клерика уровня 10 и постоянный профиль
гладиатора на стартовом WARRIOR уровне 3. Это проверка двух первых семейств
умений; весь диапазон уровней не объявляется принятым. Для restart cooldown
дополнительно продлён **только тестовой fixture**, чтобы время запуска второго
сервера не исчерпало короткий обычный cooldown. Gateway cooldowns не сбрасывает.

Нативное восстановление HP/MP в измерениях отмены останавливается только у fixture
персонажей, чтобы не принять естественную регенерацию за эффект навыка. Промежуточные
ошибки подготовки теста (World region и порядок снятия пассивных эффектов) исправлены;
финальный цикл начинается с пересозданной временной схемы.

На restart найден и исправлен реальный пограничный случай профиля уровня 10:
native human ascension cap временно понижал уровень до 9 и обрезал почти полную
MP до загрузки C3 synchronization. Новый profile-only loader восстанавливает
сохранённый уровень до создания stats/загрузки vitals, без изменения EXP или квестов.

## Что остаётся для общей игровой приёмки

1. Два настоящих владельца: assist on/off, follow/stay, summon/dismiss, logout/relog,
   смерть и смена карты; действия одного не меняют второго.
2. Визуальные анимации, поворот и выбор цели; серия при resist/dodge и окно chain;
   сравнение реальных MP/cooldowns в UI и после повторного summon/restart.
3. Проверенные стены/лестницы/узкие места, короткое сближение на native скорости;
   `stay` и недоступная поверхность не позволяют приблизиться. Численные границы
   подхода и общий cast/follow arbitration проверены автоматически; визуальная
   проходимость конкретных мест ещё не проверялась.
4. Квест 1102 в двух клиентах: финальный удар навыком, progress владельца без
   второго журнала/добавочной награды. Existing quest authorization сохранена;
   общий live сценарий с новым заклинанием остаётся в клиентской матрице.
5. Поддержанные роли на иных уровнях, оружие/ресурсы, native abnormal states,
   нагрузка нескольких компаньонов и reload флагов. Полная матрица — C8.

## Включение и риски

`ai.companions.combat.skills.enabled=false` по умолчанию; рабочий сервер/клиент
этим этапом не обновлялись. Отдельный флаг позволяет вернуть прежний basic assist.
Изменения native Skill/Effect/LifeStats ограничены точками расширения и ownership
ожидающего lethal hit; обычные игроки используют прежнюю обработку без reservation
token. Совместные гонки native эффектов проверены unit-тестами, но общий нагрузочный
прогон ещё нужен. При отмене после списания стоимости MP/cooldown не возвращаются.

SQL-схема не менялась. Нет world simulation, LLM, самостоятельных жителей,
неограниченного каталога навыков, AoE/DoT/summons, новых наград или offline farm.
Следующий этап кода — C5; клиентская приёмка C1–C4 остаётся отложенной.
