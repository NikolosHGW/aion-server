## Свежая MariaDB 11.4 и две JVM

`CompanionC3RuntimeProbe` запускает настоящий GameServer и native data 4.8
на отдельной свежей схеме из `aion_gs.sql`. Фазы `create` и `restore` выполняются
в отдельных процессах. Фактические результаты: `C3_RUNTIME_PASS phase=create`
и `C3_RUNTIME_PASS phase=restore`.

| Сценарий | Результат |
|---|---|
| Два аккаунта, список персонажей каждого | Только персонажи своего аккаунта |
| Выбор чужого образца или другой фракции | Отказ до создания тела |
| Клерик-образец 65 уровня с изменёнными face/hair/voice/height и большой суммой kinah | Новое тело PRIEST level 1; точная внешность, без имущества/уровня образца |
| Уникальность отображаемого имени | Повторная резервация имени другим владельцем отклонена БД |
| Изменить appearance и удалить образец | Blueprint и внешность тела сохранены |
| Повторить create без образца, в том числе в новой JVM | ALREADY_EXISTS, тот же ID и claim |
| Назначить alias | `[AI:C]Vasya` виден в модели Player; native DB-имя неизменно |
| Подставить другое тело/неактивную авторизацию | Gateway отклоняет изменение |
| Клерик: 1 → 9 → 10 → 65 → 10 → 1 → 10 | Класс/уровень согласованы; обычные навыки пересчитаны, stigma не выданы, noExp установлен |
| Профильные proficiency с native minLevel 9 | Навык клерика 89 появляется после продвижения, исчезает при снижении и возвращается после restart; каталог гладиатора на 10 включает 44 |
| Повтор синхронизации на том же уровне | Нет лечения или сброса cooldowns |
| Restart на точной границе 10 уровня | Клерик level 10 без фиктивного выполнения ascension quest |
| Раненое тело и cooldown после restart | Раненое состояние и cooldown сохраняются |
| Предметы и журнал квестов до/после развития | Нет новых предметов-наград/записей квестов |
| Второй, гладиаторский профиль | Своё отдельное стартовое WARRIOR тело, не изменённое развитием первого |
| Число persistent тел после повтора и restart | Ровно два для двух владельцев |

Начальный тест ошибочно ожидал нулевую kinah. В native `player_initial_data.xml`
новому персонажу положен стартовый набор, включая 1000 kinah. Проверка исправлена:
сверяет именно штатный стартовый объём класса и отсутствие денег/экземпляров вещей
образца. Другая правка самого probe использовала штатный setter cooldown вместо
прямой записи в ещё не созданную map. После исправлений схема создана заново,
обе фазы прошли целиком.

Финальная сверка с `SkillLearnService` также выявила advanced-class навыки,
записанные с `minLevel=9`. Подбор исправлен: для развитого класса учитываются и
его ранние навыки, и начальное семейство, с native порядком от старших уровней
к младшим. Добавлены проверки конкретных proficiency; окончательный прогон
обеих JVM выполнен на новой свежей схеме после этого исправления.

При level 10 native offline loader без ascension quest восстанавливает промежуточный
level 9. Новый проверенный gateway корректирует его **до spawn**, не меняя обычное
поведение людей и не создавая вторую quest history. Проверка restart покрывает
именно этот крайний случай.

Probe проверяет доменный gateway, а не клиентский вход: разрешение lease передаётся
явным тестовым supplier. Production подключает текущую owner lease, реальные
connection/world checks и feature flags. Fake connection не создаётся. Login server
в этом тесте не запускается; сообщение о неудачном соединении с отдельным тестовым
login-портом ожидаемо. Handlers нативно скомпилированы при старте GameServer.

## Воспроизведение и ограничения

Отдельная схема `ai_c3_runtime` на `127.0.0.1:53411`, URL
`jdbc:mysql://127.0.0.1:53411/ai_c3_runtime?...`; тестовый GS `127.0.0.1:17781`,
неиспользуемый login endpoint `127.0.0.1:19021`. Нужны config, data 4.8,
собранные classes/test-classes и native зависимости. Сначала `CompanionC3RuntimeProbe create`,
после завершения JVM — `CompanionC3RuntimeProbe restore`. Защитная проверка URL
отказывается работать с другой БД. Рабочая база не изменена. Временный контейнер
после окончания проверки остановлен; логи сохранены вне репозитория.

Клиентская приёмка отложена владельцем. Не проверены отображение всей внешности
и кириллицы в клиенте, live level-up с двумя подключёнными владельцами, packet/UI
обновление класса, реальные смерти/касты и нагрузочный бюджет. Native прогрессия
клерика проверена до 65; остальные классы не объявляются полноценно принятыми
по одному общему алгоритму. Боевое/лечебное использование навыков остаётся C4.

Будущий игровой проход: два обычных владельца → разные образцы/пол/ник → summon →
уровни 9/10 и повторный summon → ранение/cooldown → logout/restart → выключение
profile flag. Проверить отсутствие влияния на второго владельца, независимость
от образца и видимый неизменяемый AI-префикс. Графический редактор — C7.
