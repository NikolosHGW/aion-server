# ADR-0010: создание компаньона по образцу персонажа аккаунта

Статус: Accepted — продуктовый контракт подтверждён владельцем 2026-11-06.

База: `3e667527e`, `integration/ai-4.8`. Реализация и приёмка отдельно:
[C3](IMPLEMENTATION_PLAN_C3.md), [проверки](C3_VALIDATION_2026-11-06.md).

## Решение

Игрок использует штатный редактор Aion, создавая обычного персонажа с желаемой
внешностью. В игре он выбирает персонажа **своего аккаунта**, включая текущего,
и создаёт по нему отдельного постоянного компаньона. Только внешность (включая
пол, голос и расу) и класс попадают в снимок. Предметы, деньги, навыки, уровень,
опыт, квесты, легион и прочий прогресс образца не читаются и не копируются.

Это значение на момент создания, а не связь с персонажем. В claim нет ID или FK
образца; его последующие изменения/удаление не влияют на компаньона. Если образец
являлся самим владельцем, удаление владельца по-прежнему подчиняется отдельным
правилам ownership из ADR-0006; независимость снимка не отменяет эту связь.

Имя по умолчанию берётся у образца. Пользователь может задать другой ник при
создании. Отображаемое имя всегда `[AI:C]Ник` для компаньона; `[AI:P]` зарезервирован
для будущего самостоятельного AI-персонажа. Префикс собирает сервер; поля для
редактирования префикса нет. При лимите runtime-имени 16 символов ник содержит
2–10 латинских/кириллических букв. Слишком длинный исходный ник требует нового
ника, а не неявного обрезания. Имена профилей уникальны независимо от online.

Класс закрепляется один раз. У развитого образца копируется точный класс.
У стартового WARRIOR/PRIEST и т. п. владелец сразу выбирает допустимую специализацию
этого семейства: не требуется отдельно прокачивать образец до вознесения.
Профиль хранит выбранный развитый класс; до уровня 10 тело использует его стартовый
класс, с 10 — выбранную специализацию. Смена роли и последующее переименование
не входят в этот срез.

Первый вариант требует одной фракции у владельца и образца. Межфракционные
отношения остаются будущим отдельным проектированием, не следствием копирования
внешности. Все native классы представимы в профиле; это не обещает готовых AI-ротаций
всех классов. Первые боевые роли C4 — гладиатор и клерик.

## Границы реализации

Дополняется, а не переписывается исторический [ADR-0006](ADR-0006-PRODUCT-COMPANION-CREATION.md):
закрытый host account, новое native тело, claim/binding и восстановление после
сбоя остаются. В claim до создания тела сохраняются immutable blueprint и
уникальное отображаемое имя. Повтор использует тот же снимок, даже без образца.

Штатный `newPlayer` создаёт собственный стартовый набор и начальные навыки тела
по server data; это не перенос имущества/навыков образца. Последующее развитие
синхронизируется только с владельцем, без дополнительной доли XP и level-up наград.

Первый интерфейс — `//companion sources/create`; графическая панель остаётся C7.
Обычный character-selection протокол и клиентский редактор не модифицируются.
ADR-0001…0006 и их validation logs остаются историческими документами;
ADR-0007…0009 продолжают иметь статус Proposed.
