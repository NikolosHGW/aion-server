# Матрица приёмки C1–C8

Текущий документ. Исторические ADR/validation logs не переписывает.
Статусы: **AUTO** — проверено автоматикой; **NATIVE** — настоящий сервер/БД с явно
описанными fixture seams; **CLIENT PENDING** — проверить двумя обычными аккаунтами.
Ни одна отметка NATIVE не означает автоматически CLIENT PASS.

## Совместный игровой проход

Все пункты ниже **PENDING**. В отдельном validation log записать commit, конфиг,
аккаунты/классы/уровни/карту, результат, логи и при необходимости видео. Не вписывать
PASS задним числом без фактической проверки.

1. Два обычных аккаунта создают спутников по своим source-персонажам: один гладиатор,
   второй клерик. Проверить внешний вид/AI-имя, отсутствие копирования денег/шмота,
   повтор create без дубля, недоступность чужого source.
2. Одновременно summon, follow, rest, support. Выход/команды первого не затрагивают
   второго. Повторный вход даёт право только новой сессии; старые команды не действуют.
3. На Поэте пройти прямую, угол, склон, препятствие. Проверить local move, stay,
   ограниченные попытки при застревании и ручное возобновление follow.
4. На разрешённой цели проверить помощь бойца, лечение владельца, mana/cooldowns,
   отмену каста через rest/dismiss. Чужого владельца клерик не лечит.
5. Ранить/убить владельца и спутника отдельно; проверить cleanup и resummon.
   Затем перелёт/транспорт, переход карты, instance, relog, разрыв соединения.
6. Надеть и снять подходящую экипировку, использовать зелье. Проверить недопустимые
   предметы, уровень и класс. give/take → logout → relog, повтор receipt, оба инвентаря.
7. Выполнить 1102, затем 1120: выбрать занятие → принять лично → помогать в реальном
   бою → сдать лично. Проверить ровно один прогресс/набор наград владельцу, отсутствие
   отдельной доли/журнала спутника, подсказки и переключение целей.
8. Перезапустить тестовый сервер с активным состоянием и повторить summon/status.
   Проверить вещи, выбранное задание, native прогресс, ресурсы/cooldowns.
9. Проверить выключенные flags и возврат к работе; после отключения нет тел,
   движения, отложенного урона/лечения, потерянных lease или дубликатов.

## Откат

| Действие | Ожидаемый эффект |
|---|---|
| `activity rest` / `assist off` | Остановить помощь и pending cast; rest также движение |
| `dismiss` | Cleanup и checkpoint своего тела; intent остаётся |
| `combat.skills.enabled=false` | Отмена pending skill; остаётся ранее разрешённая basic помощь |
| `navigation.enabled=false` | Отмена ручного назначения; bounded follow остаётся |
| `activities.enabled=false` | Закрыть новые команды, сохранив старые интерфейсы |
| Убрать quest ID из обоих списков / выключить quest combat | Отозвать соответствующий боевой допуск, не выдавать награды и не трогать native journal |
| `items.enabled=false` | Запретить новые действия и отменить исполнение pending transfer на logout |
| `companions.enabled=false` / `ai.enabled=false` | Остановить сессии, очистить мир/таймеры, сохранить checkpoint |

Ключи здесь сокращены; полный префикс — `ai.companions.` (кроме `ai.enabled`).
Конфигурационные файлы применяются при запуске; для runtime-изменения нужен существующий
проверенный механизм изменения этих полей. Новый admin live-reload gateway не создавался.
Откат Git до C4 требует отключённых AI и чистой тестовой БД соответствующей версии;
совместимость downgrade новых SQL-схем не обещается. Коммиты C5–C8 — точки истории.
