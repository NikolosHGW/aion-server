## Согласование изменений

- Сохранены AI cleanup и scheduler shutdown вместе с новым отключением сети
  и обработкой отложенного выхода игроков из upstream.
- В `PlayerController` объединены хуки компаньона и новые проверки обычного
  персонажа, транспорта и времени автоатаки.
- Для обычного движения сохранены новые немедленные поправки скорости
  вперёд/назад/вбок; для AI сохранён отдельный override скорости. Остановка
  движения не возвращает удалённую upstream обработку падения.
- Старый `GEO_ENABLE` заменён проверкой `GeoDataConfig.Mode.ON`. Неполная
  геометрия и отключённый LoS по-прежнему запрещают движение компаньона.
- Создание тела адаптировано к `PlayerAppearance.setHeightScale`; форматирование
  предметов в описании наград — к новой сигнатуре `ChatUtil.itemName`.
- Обе динамически загружаемые команды, `aiplayer` и `companion`, переведены
  на новый конструктор справки `AdminCommand`. Добавлен тест их реальной компиляции:
  одна только сборка обычных исходников этот сбой не обнаруживала.
- Проверки исходного кода обновлены для переименования `criticalProcEffect`
  и переносов строк Windows; проверяемые ограничения AI сохранены.
- В Docker-инициализации удалена временная правка запятой в старой SQL-схеме:
  upstream уже исправил первопричину. `.gitattributes` сохраняет этот скрипт
  с LF, необходимыми для Linux-контейнера.

## Чистая база

Владелец выбрал создание базы заново. Отдельный перенос данных прежнего AI MVP
не добавляется; резервные копии экспериментальной БД не требуются для разработки.

Полные схемы для новой пустой БД:

- `login-server/sql/aion_ls.sql` — аккаунты и регистрация game server;
- `game-server/sql/aion_gs.sql` — игровая БД, включая все три таблицы AI;
- `chat-server/sql/aion_cs.sql` — чат.

Это SQL-файлы в Git, а не автоматически выполняемые Java-миграции. При создании
нового Docker volume их импортирует `docker/mysql/init/01-init-aion.sh`.
При уже существующем volume начальная инициализация повторно не запускается.
Для свежей схемы не нужно дополнительно выполнять `update.sql`,
`ai_companion_persistence.sql` или `ai_companion_creation.sql`.
Полные схемы содержат `DROP TABLE`: они предназначены для новой пустой базы.

Новая база не содержит прежних аккаунтов и персонажей. Значения `13/Test` и
`106168` в локальном Docker-профиле — прежние тестовые ID; после создания
аккаунтов нужно настроить актуальный закрытый AI-host и, если используется
режим шаблона, template ID. Базовый `config/main/ai.properties` оставляет функции
AI выключенными; локальный `docker/server-config/game/mygs.properties`
содержит явные экспериментальные включения и требует настройки под новую БД.

## Проверки

Полная сборка с Java 25:

```text
mvn -B -T 4 -Dmaven.source.skip=true -Dmaven.test.skip=false package
```

Результат: **254 теста, 0 failures, 0 errors, 0 skipped**:
248 game-server, 5 login-server, 1 commons. Собраны все модули, включая chat-server.

В отдельном MariaDB 11.4 контейнере:

- импортированы свежие схемы из репозитория, без дампа существующей БД;
- выполнен Docker init-скрипт: 64 таблицы GS, 8 LS, 1 CS, все три таблицы AI;
  для этой проверки команда `mysql` указывала на совместимый клиент `mariadb`;
- запущены LS и GS, скомпилированы игровые обработчики, установлена связь GS→LS;
- через штатный сервис создания созданы тестовый владелец и настоящий level-1
  компаньон, без поддельного клиентского соединения;
- повторное создание вернуло то же тело; после полного перезапуска GS
  загрузились тот же ID, внешность, стартовый инвентарь, навыки и цель;
- реальный план квеста 1102 совпал с обновлёнными обработчиками и manifest спавнов;
- проверены сопоставление боевого вклада компаньона владельцу, очистка реестра,
  поправки скорости 1/0.6/0.8, AI override и его снятие при остановке;
- GS корректно завершился с объединённой процедурой shutdown.

Ограничения: это серверные проверки без входа пользователя в клиент. Они не
подтверждают полный игровой цикл summon/follow/бой/награда под нагрузкой.
Образ MySQL 8.4 и полный Docker-образ серверов в этой проверке не запускались.
В данных остаются предупреждения о отсутствующих trade lists, motion times и
некоторых quest NPC spawns; startup завершается успешно, квест 1102 проверен отдельно.
Действующие игровые процессы и базы не обновлялись.

## Следующее обновление

1. Продолжать работу в `integration/ai-4.8`; не менять `feature/ai-mvp`.
2. Получить проверенное обновление 4.8 в форк и обновить `origin/4.8` через fetch.
3. Выполнить `git merge --no-ff --no-commit origin/4.8` в интеграционной ветке.
4. При конфликтах сверять обе реализации, особенно movement, combat, logout,
   shutdown, схему БД и динамические обработчики.
5. Запустить полную сборку с тестами, сервер на чистой тестовой базе и ручную
   проверку обычного персонажа и компаньона. После проверок зафиксировать merge.

Когда появятся данные реальных игроков, стратегию сохранения БД потребуется
пересмотреть: пересоздание базы удаляет прогресс и не заменяет миграцию схемы.
